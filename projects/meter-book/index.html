SaaS / Concept brief

Meter Book

A readable ledger for usage.

Graduated dial
Study topics
  • Usage metering
  • Event processing
  • Billing

The question

A customer sees a monthly total. Which requests made up that number? The proposed ledger would let a team follow an invoice line back to the events behind it.

Proposed architecture

A collector would record events using stable identifiers. A rating step would apply the price effective at the time of use and a statement view would show how individual entries add up.

First experiment

Replay the same batch twice and introduce a late event after a statement closes. Check whether a reviewer can explain the total, the duplicate and the adjustment.

Proposed flow

  1. Receive event
  2. Deduplicate
  3. Apply rate
  4. Review statement
