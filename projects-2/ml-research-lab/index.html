Research brief

A change in a score can come from the model, the split or the data itself. The proposed lab would keep those choices visible so a researcher could repeat a comparison and explain the differences.

Planned features

Experiments could pin a dataset version, register a baseline and compare errors by subgroup or time window. Each run would carry its parameters, split definition and reproducibility notes.

Proposed architecture

A dataset registry would supply immutable snapshots. An experiment runner would execute a recorded configuration and write predictions to an artifact store. A comparison view would group compatible runs and highlight changed inputs.
